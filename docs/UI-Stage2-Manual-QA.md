# UI Stage 2 人工验收清单

**本清单是给人在真机上执行的。自动化覆盖了 JVM 单测、Robolectric 导航测试、lint、
Manifest 类校验与 APK 构建 —— 视觉与真实交互没有跑过。**

> **环境声明（必须先读）**
> 本轮开发环境**没有模拟器，也没有连过真机**（`adb devices` 无设备）。
> 因此：
> * 本文档中**没有任何一条被标记为“已验证”**；
> * `docs/UI-Stage2-Report.md` 里也**不声称**完成了视觉验收；
> * 交付物中**没有运行截图** —— 仓库里的设计示意图是设计稿，不能冒充运行截图。
> 下面每一条都需要人在设备上跑一遍并回填结论。
>
> 安装包：`android/app/build/outputs/apk/debug/app-debug.apk`（debug 签名，可 `adb install -r`）；
> 安装会**替换同包名**的现有应用（`com.androidmcphub.app`），已保存的服务器配置与令牌保留在应用私有目录，
> 卸载才会清除 —— 是否安装由你自己决定。

建议设备：Android 13/14/15 各一台（`minSdk 26`、`targetSdk 35`）；至少覆盖一台 Android 13+
（有通知权限弹窗）与一台 **Android 16（强制边到边）**。

## A. 本轮头号目标：导航可靠性（**最重要，先跑这一段**）

| # | 场景 | 步骤 | 通过标准 |
| --- | --- | --- | --- |
| A1 | 真机故障原场景 | 首页点「工具目录」进工具页 → 点底栏「首页」 | 回到首页，底栏高亮在「首页」，页面上没有任何工具页残留 |
| A2 | 再来一次 | A1 之后**再**点「工具目录」→ 底栏「首页」，重复 5 次 | 每次都稳定回首页；不会出现“点首页却进了工具页” |
| A3 | 服务页同路径 | 首页「连接诊断」/服务页进服务 → 底栏「首页」 | 同上；服务页进入后也能回首页 |
| A4 | 四标签任意切换 | 首页→工具→服务→设置→服务→首页→设置（打乱顺序，每页停留 1 秒） | 每次切换到位、标题与高亮一致，不出现白屏/错页 |
| A5 | 连点当前标签 | 在「工具」页连点底栏「工具」5 次 | 页面不重建（搜索词与筛选不清空）、不闪、不崩 |
| A6 | 二级页隐藏底栏 | 进「工具详情」「连接详情」「服务器与设备配置」「高级连接参数」「设备令牌管理」「连接诊断」「工具说明」 | 这些页**没有底栏**；左上角有返回箭头 |
| A7 | 二级页返回 | 在上述每个二级页按左上箭头、再各按一次系统返回键 | 回到**来源页**（从诊断进的就回诊断、从设置进的就回设置），不是一律回首页 |
| A8 | 系统返回键 | 工具页按返回；服务页按返回；首页按返回 | 首页按返回退出应用；其它三个顶层 tab 按返回回到首页（不是逐个弹栈） |
| A9 | 状态保留 | 工具页搜索 `battery` + 选「设备」分类 → 切到服务页 → 切回工具页 | 搜索词与分类还在 |
| A10 | 进程重建 | 打开开发者选项「不保留活动」，在工具详情页退到桌面再切回 | 应用不崩；导航回到合理位置（不出现空白页或错位高亮） |

## B. 信息架构（本轮重整的部分）

| # | 场景 | 步骤 | 通过标准 |
| --- | --- | --- | --- |
| B1 | 首页是否够轻 | 打开首页 | 只有：连接状态卡（含连接/断开、连接详情）、设备概况、最近一次诊断摘要、两个快捷入口、最近活动；**看不到**服务器 URL 输入框、令牌框、超时/重连参数 |
| B2 | 首页不重复底栏 | 看首页「快捷入口」卡 | 只有 2 项（工具目录、连接诊断），不是把四个标签又列一遍 |
| B3 | 长 URL 不撑卡片 | 在设置里填一个很长的服务器地址（例如 `wss://very-long-subdomain.example.internal.company.net:8443/phone/ws`）→ 回首页与设置主页 | 只显示 `host:port` 形式，单行省略号截断，卡片不变形、不横向溢出 |
| B4 | 工具页先看工具 | 打开工具页 | 第一屏就是搜索框 + 分类胶囊 + 工具卡片；**没有**大段协议说明/实现原理/`phone_ping` 长篇解释 |
| B5 | 工具说明搬家 | 点工具页右上「说明」 | 解释（本机能力从哪来、为什么有些工具是灰的、其他来源、`phone_ping` 为何不在列表）在这里；有「本机能力授权」入口能进设置 |
| B6 | 工具数量与状态 | 看工具页统计行 | 显示「本机能力 1 个 · 当前可用 1 个」（总开关开）/「当前可用 0 个」（总开关关），并有「授权已开启/已关闭」标签；**列表里只有 `battery_get_status`**，没有任何假工具 |
| B7 | 服务页诚实空状态 | 打开服务页 | 「我的服务」显示「0 个」与「尚未添加 MCP 服务」；添加按钮**是灰的**并写「即将支持」，点它没有任何“保存成功”的假提示 |
| B8 | 服务页不夹带诊断 | 看服务页 | 不显示 Ping 日志、不显示 Cloudflare/WebSocket 连接诊断（那些在设置 → 连接诊断） |
| B9 | 设置主页不再堆表单 | 打开设置 | 只有分组入口（服务器与设备配置／高级连接参数／设备令牌管理／能力授权开关／连接诊断／清空日志／清除最近一次错误／关于）；**十个输入框一个都不在首页** |
| B10 | 三个设置子页 | 分别进「服务器与设备配置」「高级连接参数」「设备令牌管理」 | 各页标题清晰、有返回键；服务器 URL + 设备 ID 在第一页、7 个数值参数在第二页、令牌在第三页 |
| B11 | 用户看不到开发文档路径 | 通读四个页面与所有子页 | 界面上**不出现** `docs/UI-Stage1-Manual-QA.md`、`UI-Stage1-Report.md` 这类内部文档路径 |

## C. 视觉与密度（需要在设备上肉眼判断）

| # | 场景 | 通过标准 |
| --- | --- | --- |
| C1 | 页面长度 | 设置主页一屏内能看完分组；服务器与设备配置页不需要滚很长时间；没有因为组件自带 padding + 父布局又加一次而出现的“虚胖”表单 |
| C2 | 卡片高度 | 卡片高度由内容决定，不出现为填满屏幕而留的大片空白 |
| C3 | 字号（默认设置下） | 页面标题≈22sp、卡片标题 16–18sp、正文 14–15sp、次要 12–13sp；没有明显过大的文字 |
| C4 | 底栏 | 四个标签图标/文字比例协调（图标 22dp）；选中态清楚但不膨胀；**不遮挡**页面最后一项内容；滚动时不上下乱跳 |
| C5 | 触摸目标 | 设置里的每一行、每个开关、每个按钮都能轻松点中（行高≥52dp）；不会出现“只有小开关能点、整行点不动” |
| C6 | 深色模式 | 切到深色后四页 + 三个子页 + 卡片 + 状态胶囊 + 日志级别色都跟随；无白底黑字残留、无低对比不可读文本 |
| C7 | 系统字体放大 | 字体调到最大（或显示大小 1.3×）：标题/正文不重叠、状态文案与设备 ID 不截断到不可辨；卡片高度自适应 |
| C8 | Android 16 边到边 | 状态栏与手势条区域内容不被遮挡；键盘弹出时输入框不被挡住（设置子页会用到 `imePadding`） |

## D. 功能完整性（10 项必须都还在 —— 任务书 §6）

| # | 功能 | 现在的入口 | 通过标准 |
| --- | --- | --- | --- |
| D1 | WebSocket 连接 / 断开 | 首页「连接状态」卡 | 「已断开」时按钮是「连接」；连接中/已连接时是「断开」；行为与改版前一致 |
| D2 | 服务器 URL 配置 | 设置 → 服务器与设备配置 | 可输入可保存；placeholder 仍是 `wss://<host>/phone/ws` |
| D3 | 设备 ID 配置 | 设置 → 服务器与设备配置 | 可输入可保存；首页不显示完整 ID |
| D4 | 设备令牌 输入 / 显示隐藏 / 清除 | 设置 → 设备令牌管理 | 默认打码；「显示/隐藏」切换；「清除已保存的令牌」点后状态变「尚未设置」；**界面从不显示令牌长度或前后几位** |
| D5 | 配置保存与原有校验 | 三个设置子页各自的「保存配置 / 保存令牌」 | 保存弹 Snackbar；清空必填项保存要有明确错误提示（不静默失败）；退出应用重进值仍在 |
| D6 | 超时与重连参数 | 设置 → 高级连接参数 | 7 个数值（ping 超时 / 心跳周期 / 初始重连间隔 / 最大重连间隔 / 抖动比例 / 最大挂起请求数 / 单帧字节上限）都在，可以改并保存 |
| D7 | 本机能力授权总开关 | 设置主页「安全与授权」 | 开关可切换、状态准确；关掉后工具页立刻变「总开关已关闭 / 当前可用 0 个」，**不需要重连** |
| D8 | 连接诊断与 ping 信息 | 设置主页 → 连接诊断；首页 ping 摘要 | 当前状态、前台服务、服务器、设备 ID、连接代次；最近一次 ping 的 RTT / 单向延迟 / 服务端时间戳 / 本机收到时刻；长按 request_id 复制并提示「已复制 request_id」；**诊断页不会触发连接或断开** |
| D9 | 日志查看与清理 | 设置主页 → 连接诊断 | 计 `N/200`；级别色与时间格式同改版前；点「清空」后列表空、首页最近活动同步为空 |
| D10 | 最近一次错误的展示与清除 | 首页 ping 摘要（错误文本）+ 设置主页「清除最近一次错误」 | 出现错误时能看到；点清除后消失 |

## E. 重点回归：不许退化的三件事

| # | 检查点 | 怎么做 | 通过标准 |
| --- | --- | --- | --- |
| E1 | 切页不切断连接 | 连上后在四个页面 + 子页之间来回切 10 次 | 状态保持「已连接（代次 N）」，代次**不变**，日志无重新握手记录 |
| E2 | 导航不反复创建 `PhoneLinkService` | 连接后切页、进出子页；`adb shell dumpsys activity services com.androidmcphub.app` | 只有一个服务实例；`onCreate` 不被反复调用；断开后按既有生命周期结束 |
| E3 | 重组不产生副作用 | 在设置子页反复输入、切页；在首页等倒计时刷新 | 输入不触发连接/保存；倒计时只改文案；日志不出现重绘导致的重复请求 |

## F. 回归：连接失败与令牌安全

| # | 项 | 期望 |
| --- | --- | --- |
| F1 | 连接失败状态 | 指向不存在的域名：显示「重连等待（第 N 次，Xs 后）」且倒计时在走；仍能「断开」 |
| F2 | 认证失败 / 被撤销 | 分别显示「认证失败」「凭据已被撤销」（带原因），文案仍来自同一个状态映射 |
| F3 | 令牌加密存储 | `adb shell run-as com.androidmcphub.app ls shared_prefs` 里**不应出现**明文令牌；关闭再打开令牌页，明文只在点「显示」后出现 |
| F4 | 通知权限 | Android 13+ 首次进入请求通知权限；拒绝后连接功能不受影响；授权后前台服务通知可见 |
| F5 | 前后台切换 | 连接成功后回桌面 1 分钟再切回：连接保持（前台服务仍在）、首页状态与日志连续、不重复建连 |

## H. 明确的未实现功能（验收时不要当成缺陷）

1. 第三方 MCP 服务的接入：服务页只有诚实的空状态，添加按钮是禁用的「即将支持」；
2. 本地 HTTP MCP 中转；
3. 协议级授权状态机与「允许 / 拒绝」确认交互（工具详情页只写了将来落点，没有假按钮）；
4. 工具目录只有本机能力（当前仅 `battery_get_status`），不显示服务端下发的工具；
5. 应用内主题切换开关（深色模式只跟随系统）；
6. 任务持久化与查询接口（授权/执行任务的生命周期后续才做）。
