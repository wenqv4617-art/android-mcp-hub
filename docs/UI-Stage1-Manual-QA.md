# UI Stage 1 人工验收清单

**本清单是给人在真机上执行的。自动化只覆盖了 JVM 单测、lint、Manifest 类校验与 APK 构建 —— 视觉与交互没有跑过。**

> **环境声明（必须先读）**
> 本轮开发环境（Android SDK + Gradle 8.11.1 + AGP 8.7.3）**没有模拟器、也没有连过真机**：
> `adb devices` 无设备、`emulator` 二进制不可用。因此：
> * 本文档中**没有任何一条被标记为"已验证"**；
> * `docs/UI-Stage1-Report.md` 里也**不声称**完成了视觉验收；
> * 交付物中没有"运行截图"——设计示意图是设计稿，不能冒充运行截图。
> 下面每一条都需要人在设备上跑一遍并回填结论。
>
> 安装包：`android/app/build/outputs/apk/debug/app-debug.apk`（debug 签名，可直接 `adb install -r`）。

建议设备：Android 13/14/15 各一台（`minSdk 26`、`targetSdk 35`）；至少覆盖一台
Android 13+（有通知权限弹窗）与一台 Android 16（强制边到边）。

## A. 必须覆盖的 15 项

| # | 场景 | 步骤 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 冷启动 | 杀掉进程后重新打开 App | 先出现 Splash 启动图，随后进入首页；**不自动连接**（状态为「已断开」）；无崩溃、无 ANR |
| 2 | 四页切换 | 依次点底部「首页 / 工具 / 服务 / 设置」 | 每页即时切换，底栏高亮跟随；四页标题分别为 Android MCP Hub / 工具 / 服务 / 设置 |
| 3 | 系统返回键 | 在首页按返回；进「工具详情」后按返回；进「添加 MCP 服务器」后按返回 | 首页按返回退出应用（不残留后台界面）；子页按返回回到来源页（工具页 / 服务页）；**返回键不会把四个 tab 逐个弹栈** |
| 4 | 连接 / 断开 | 设置页填 `wss://<host>/phone/ws` 与设备 ID → 保存 → 回首页点「连接」 | 状态依次「连接中」→「已连接（代次 N）」；按钮变成「断开」；点「断开」后回到「已断开」。（需要一个可用的 Worker 地址） |
| 5 | 连接失败状态 | 把服务器地址改成不存在的域名或错误路径 → 连接 | 状态显示「重连等待（第 N 次，Xs 后）」倒计时在走；多次失败后仍能「断开」；若是认证失败/被撤销，分别显示「认证失败」「凭据已被撤销」（含原因） |
| 6 | 令牌显示 / 隐藏 | 设置页「设备令牌」输入框右侧点「显示/隐藏」 | 默认打码（●）；点击后明文可见，再点恢复打码；输入框内容不被清空 |
| 7 | 保存配置 | 修改 8 个配置字段中的任意几个（含服务器 URL、设备 ID、时间/重连/并发数值）→ 点「保存配置」 | 弹出 Snackbar 提示保存结果；退出应用重进后这些值仍在；**清空必填项后保存应有明确错误提示（不会静默失败）** |
| 8 | 能力开关 | 设置页「允许服务端调用本机只读能力」打开/关闭 | 开关状态立刻影响工具页的可用状态标签（已启用 ⇄ 总开关已关闭）；**不重连也生效**；杀掉进程重进后保持 |
| 9 | 工具列表 | 打开「工具」页 | 至少看到 `battery_get_status`（分类「设备」、来源「本机能力」）；搜索框输入 `battery` 只剩它，输入乱码显示空状态「没有匹配的工具」；分类胶囊筛选正常；点卡片进详情，参数区显示「这个工具不接受任何参数。」；「其他来源」显示两个「未开放」标签 |
| 10 | 服务空状态 | 打开「服务」页；点右上「+」或「添加 MCP 服务器」 | 服务页显示「尚未添加 MCP 服务」空状态与说明；**不显示任何假的已接入服务**；点按钮进入表单预览页，点「保存并拉取工具」显示的是"未开放、没有保存、也没有连接"的提示，**不是**成功提示 |
| 11 | Ping 诊断 | 连接成功后从设置页进「连接诊断」；有 ping 后在首页 ping 摘要点「连接诊断」 | 诊断页显示当前状态、最近一次 ping 的 RTT/单向延迟/服务端时间戳/本机收到时刻；长按 request_id 复制并看到「已复制 request_id」提示；**诊断页不触发连接或断开** |
| 12 | 日志清空 | 连接一段时间产生日志 → 诊断页点「清空」 | 日志列表变空并显示空状态；返回首页「最近活动」同步为空；计数从 `N/200` 归零 |
| 13 | 深色模式 | 系统设置切到深色 → 回到 App（或重启） | 四个页面、卡片、状态胶囊、日志级别色都跟随深色；无白底黑字残留、无不可读的低对比文本 |
| 14 | 系统字体放大 | 系统字体调到最大（或显示大小 1.3×） | 标题/正文不重叠、不截断关键信息（设备 ID、状态文案）；卡片高度自适应；底部导航文字不被裁切 |
| 15 | 前后台切换 | 连接成功后按 Home 回桌面等 1 分钟再切回；再从最近任务返回 | 连接**保持**（前台服务仍在运行）；首页状态与日志连续（没有整段丢失）；返回后不重复建连 |

## B. 本轮重点：不许退化的三件事

| # | 检查点 | 怎么做 | 通过标准 |
| --- | --- | --- | --- |
| B1 | 切页不切断连接 | 连上之后在四个页面之间来回切换 10 次，再看状态与诊断页日志 | 状态保持「已连接（代次 N）」，代次**不变**，日志中没有重新握手/重连记录 |
| B2 | 导航不反复创建 `PhoneLinkService` | 连接后切页、进出子页；用 `adb shell dumpsys activity services com.androidmcphub.app` 观察 | 服务实例只有一个；`onCreate` 不被反复调用；断开后服务按既有生命周期结束 |
| B3 | 重组不产生副作用 | 在设置页输入框反复输入/切页，在首页等待倒计时刷新；观察诊断页日志 | 输入不会触发连接/保存；倒计时只更新文案；日志里不出现"因为滚动/重绘而多发一次请求"之类的重复条目 |

## C. 回归：改版前能力必须仍可用

| # | 项 | 期望 |
| --- | --- | --- |
| C1 | 连接与断开（原首页按钮） | 与改版前行为一致（含 Idle 才能连接、连接中/已连接只能断开） |
| C2 | 最近一次 ping 的四行数据 | RTT / 单向延迟 / 服务端时间戳 / 本机收到时刻 全部仍在（现位于诊断页） |
| C3 | 最近一次错误 + 清除 | 出现错误时能显示，点「清除」后消失（首页错误提示同步消失） |
| C4 | 日志查看与清空 | 日志条数上限 200、级别色、时间格式与改版前一致 |
| C5 | 令牌加密存储 | 关闭再打开令牌输入框，明文只在点击「显示」后出现；`adb shell run-as com.androidmcphub.app ls shared_prefs` 里**不应出现**明文令牌 |
| C6 | 通知权限 | Android 13+ 首次进入时请求通知权限；拒绝后连接功能不受影响；授权后前台服务通知可见 |

## E. 明确的未实现功能（验收时不要当成缺陷）

1. 第三方 MCP 服务器的接入：添加服务是**结构预览**，不保存、不连接、不拉取工具；
2. 本地 HTTP MCP 中转；
3. 协议级授权状态机与"允许/拒绝"确认交互（只留了文案与将来落点）；
4. 工具页只有本机能力目录（当前仅 `battery_get_status`），不显示服务端下发的工具；
5. 深色模式只跟随系统，没有应用内主题切换开关（设计稿里的"主题与外观"一行未做）。
