0 · 前置条件

所有命令都在你自己的可信终端里执行。凡是 <...> 都是占位符。

项要求确认方式
Cloudflare 账号能创建 Workers 与 Durable Objectsnpx wrangler@4.149.0 whoami
Node.js≥ 20node -v
域名不需要；*.workers.dev 即可部署输出会打印地址
Android 构建（可选）JDK 17 + Android SDKjava -version

1 · 取代码并本地验证

任何一步失败都不要部署。先修好本地，再动线上。

git clone https://github.com/wenqv4617-art/android-mcp-hub.git
cd android-mcp-hub
npm ci

npm run typecheck
npm run test
npm run e2e
预期：typecheck 通过，Worker 测试与本地端到端全部通过。e2e 使用真 HTTP、真 WebSocket 和官方 MCP SDK，不依赖你的 Cloudflare 账号。

2 · 生成并注入凭据

下面的随机值只在这个页面里生成，不会离开浏览器。生成后请立刻存进密码管理器； 页面刷新或关闭后无法恢复。

2.1 设备令牌 → DEVICE_TOKENS

设备令牌明文只填进手机 App；DEVICE_TOKENS 只保存它的 SHA-256 摘要。 把摘要记录整段用 wrangler secret put 注入，不要把明文发进聊天或 Issue。

2.2 OAuth 运维口令 → OAUTH_OWNER_SECRET

这是 OAuth 同意页的口令，也是 OAuth 面的开关：不设置时整个 OAuth 返回 404。 只给 OAuth 客户端使用，不要和下面的管理令牌复用。

2.3 操作台管理令牌 → GATEWAY_ADMIN_TOKEN

只用于 /gateway 操作台与全局管理 API，永远不会下发给客户端或手机。

2.4 Android 配对码 → GATEWAY_ANDROID_PAIRING_CODE

只在「手机 → 网关」首次配对时使用。配对成功后请轮换或删除这个 Secret。

2.5 注入 Secret

npx wrangler@4.149.0 secret put DEVICE_TOKENS --config worker/wrangler.jsonc
npx wrangler@4.149.0 secret put OAUTH_OWNER_SECRET --config worker/wrangler.jsonc
npx wrangler@4.149.0 secret put GATEWAY_ADMIN_TOKEN --config worker/wrangler.jsonc
npx wrangler@4.149.0 secret put GATEWAY_ANDROID_PAIRING_CODE --config worker/wrangler.jsonc
不要在这个页面、任何网页或聊天窗口里粘贴 Cloudflare API Token。 本页面没有输入框，也不会发起网络请求。wrangler 登录请用官方 wrangler login。

2.6 可选：上游凭据 → GATEWAY_UPSTREAM_SECRETS

只有接入需要鉴权的第三方 MCP 服务时才需要。值是 JSON： {"<ownerId>/<secretRef>": "Bearer <上游凭据>"}。 键必须和操作台里填的 secretRef 对上；公开上游可以完全不设置。

3 · 配置与部署

先编辑 worker/wrangler.jsonc 的 vars（这些不是秘密）：

"GATEWAY_ENABLED": "true",
"GATEWAY_ALLOWED_URLS": "https://your-upstream.example/mcp"
  • 允许清单是精确 URL（含路径），逗号分隔，不能带 query 或 hash；
  • 生产只接受 HTTPS/443，拒绝 IP 字面量、本地域名与 URL 里的用户名密码；
  • 新增上游必须改配置并重新部署，客户端不能在运行时扩展。
npx wrangler@4.149.0 deploy --config worker/wrangler.jsonc --dry-run
npx wrangler@4.149.0 deploy --config worker/wrangler.jsonc

dry-run 应列出脚本名 android-mcp-hub、四个 DO 绑定和迁移 tag v1 / v2 / v3-gateway。已部署过的 tag 不能修改，只能追加。

4 · 部署后自检

BASE=https://<worker>.<subdomain>.workers.dev

curl -sS "$BASE/healthz"
curl -sS -o /dev/null -w '%{http_code}\n' "$BASE/mcp"      # 期望 401（未带令牌）
curl -sS -o /dev/null -w '%{http_code}\n' "$BASE/gateway"  # 期望 200
  • /healthz 应显示 gateway_enabled: true、gateway_android_pairing_configured: true； 它只回布尔值与类别，不回显凭据。
  • 若既没有 OAuth 也没有静态令牌，/mcp 会失败关闭返回 503；配置了认证但未带令牌才是 401。
  • 打开 /gateway，用管理令牌登录，添加服务、测试连接、签发客户端令牌。

5 · 客户端接入

URL

https://<worker>.<subdomain>.workers.dev/mcp

鉴权

Authorization: Bearer <客户端令牌>
或 OAuth 2.1 + PKCE（需配置 OAUTH_OWNER_SECRET）。

令牌从哪来

Android「服务 → 云端网关 → 访问令牌」，或操作台 /gateway。明文只显示一次。
这类 hub_client_* 只访问已授权的 ext_*；本机原生工具请让客户端走 OAuth。

令牌只放在 Authorization 头。不要拼进 URL、查询参数、截图或聊天记录。 每个客户端单独签发令牌；只读令牌看不到也调不了写操作。

逐客户端配置、兼容性与排障见 CLIENT_SETUP.md。
